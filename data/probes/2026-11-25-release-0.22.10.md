# Release 0.22.10 — the roster miss no longer blocks an update

The owner hit `failed: Live hero models/heroes_staging/nano/nano_v2/nano.vmdl_c is no longer in the
roster` while updating an old package, and said the updater must not gate work on a hand-rolled list.

`forge.live.resolve_hero` replaces the three slug lookups that raised. It resolves an exact slug, then
the same hero family on identity tokens with version suffixes removed, then the package's own model,
then `None` — which `forge.migrate.update_from_package` already accepts by keeping the old body. The
note (`roster-miss:<slug>-><slug>` / `:package-model` / `:no-model`) shows in job progress instead of a
refusal. Probe: `data/probes/2026-11-25-roster-is-not-an-allowlist.md`.

## The pre-commit gate refused five home paths, and one redaction truncated two logs

The first `git commit` was refused by `tools/secrets_gate.py` (the hook and CI run the same check) with
five medium `home-path-windows` findings: two scout compile logs and
`popit_apps/scout_port/server.py:429`, which defaulted `CSDK_ROOT` to `%USERPROFILE%\Downloads\Reduced_CSDK_13`.
The server now reads `CSDK_ROOT` and reports no path when it is unset; the two logs had the account
segment of the path replaced with `%USERPROFILE%` (256 → 258 and 13934 → 13936 bytes).

**The incident.** The first redaction one-liner opened the destination for writing before reading it, so both
logs were truncated to 0 bytes. They had already been staged by the refused commit, so the content was
recovered with `git checkout-index --force` from the index (blobs `4afbdf0b` and `224b3ff3`); the second
pass reads the whole file into memory before opening it for writing. Nothing was lost, but the lesson is
that a redaction reads first and writes second, and that an aborted `git add` is worth keeping until the
files it staged are known to be intact.

**Two rule collisions on the way, recorded rather than skipped.** The first commit message was passed
through a heredoc, which the family bans (`heredoc-command-limit`, 2026-11-22); the refused commit wrote
nothing and the message was re-issued as plain `-m` flags. The first redaction line also carried the same
home path into this file, so the gate refused the second commit until it was rewritten as
`%USERPROFILE%`. Both collisions are in `logs/authority/2026-11-25-heredoc-and-redaction.jsonl`.
